Match the test server and agent versions and confirm the cluster's actual networking settings before joining. Keep the agent disabled during every intermediate Android migration boot.

The phone reports SDK 36.0. The local source reference is AOSP `android16-release` system/core at `68be0c2c0006a0740d0b1809abe4717308f90d15`. Use the captured Motorola ELF as the compatibility reference. The upstream source has separate entry points to handle in the port:

- `createProcessGroupInternal` activates controllers on the UID directory and creates the PID group before attaching the process. Set up the threaded scheduling children during privileged process-group creation so callers that can apply task profiles only need task-placement access.
- `SetCgroupAction` resolves v1 task paths globally and caches file descriptors by action. Unified scheduling needs a process-relative destination based on current thread placement. Update task and process actions and their validation together.
- `get_sched_policy` currently compares a controller-relative path against a single legacy group name. Decode the CPU and cpuset components of the unified path so policy getters still agree with their setters and CPU-to-cpuset fallback works.
- The task-attribute patch handles memory and I/O operations invoked on a TID under the proposed `vegas26-sched` subtree. It resolves those files in the enclosing process domain. Process-wide attribute lookup already targets the PID directory. The patch applies to the pinned Android 16 source. Compiled-library and on-device validation are pending. [Task-attribute patch](../patches/android16-process-domain-attributes.patch)
- The cleanup patch updates `RemoveCgroup` and boot-time empty-group cleanup to remove the scheduler-owned subtree leaf-first. A host fixture verified that populated groups, legacy groups and unrelated children are preserved. Exercise failed setup, app kill and service restart on Android. [Cleanup patch](../patches/android16-threaded-group-cleanup.patch)
- Android init's service child waits on the cgroup-activation channel before applying task profiles. The parent creates the process group and initializes the threaded subtree before signaling it. Verify this on the firmware and cover any callers outside normal service startup.

Apply the [task-attribute patch](../patches/android16-process-domain-attributes.patch), [cleanup patch](../patches/android16-threaded-group-cleanup.patch) and [placement patch](../patches/android16-threaded-group-placement.patch) in that order. ## 8. Hardware Bring-up Diagnosis and Verification Results

### iptables / kube-router agent exit diagnosis and fix

1. **Root cause**: When K3s agent started on the phone, kube-router attempted to create chain `KUBE-ROUTER-INPUT` in the `filter` table. Android `netd` previously installed rules referencing `-m bpf --object-pinned /sys/fs/bpf/netd_shared/prog_netd_skfilter_allowlist_xtbpf`. In Linux 5.15 `net/netfilter/xt_bpf.c`, `bpf_mt_check_v1` calls `bpf_prog_get_type_path` to resolve the pinned path in the caller's mount namespace. Because `scripts/debian-shell.sh` mounted a private `sysfs` without bind-mounting `/sys/fs/bpf`, the pinned BPF object path did not exist (`ENOENT`), causing `setsockopt(IPT_SO_SET_REPLACE)` to fail with `ENOENT` ("No chain/target/match by that name"), terminating the agent.
2. **Userspace quota2 match**: Android `netd` rules include the out-of-tree `quota2` match. Running `iptables-legacy-save` aborted because Debian lacked `/usr/lib/aarch64-linux-gnu/xtables/libxt_quota2.so`. Installing `xtables-addons-common` supplied the missing shared object.
3. **Control plane routing & tunnel**: The WSL control plane advertised its internal IP `172.22.126.57` over the remotedialer tunnel; aliasing `172.22.126.57/32` to `lo` on the phone kept traffic routed via `adb reverse tcp:16443 tcp:16443`.
4. **CoreDNS egress permission**: CoreDNS defaulted to running as non-root UID 65532. Android attaches BPF socket creation and sendmsg programs (`prog_netd_cgroupsock_inet_create` and `prog_netd_sendmsg4_udp4_sendmsg`) to the root cgroup v2. Unregistered UIDs without Android permissions returned `-EPERM` (`write: operation not permitted`), preventing CoreDNS from answering readiness probes on port 8181. Setting `securityContext.runAsUser: 0` on `deployment/coredns` restored socket egress; CoreDNS immediately reported `1/1 Running` and populated `kube-dns` endpoints.
